# Zero Egress

Zero egress means Solomon must keep model calls on a local endpoint unless remote egress is explicitly enabled. ZDR means a remote endpoint that contractually does not retain prompts or outputs; Solomon still treats that as boundary crossing.

## Enforcement

- `Settings.validate_egress_policy` rejects `allow_remote_egress=true` when `zero_egress_mode=true`.
- Remote embeddings require the separate `allow_remote_embedding_egress=true` opt-in, an OpenAI-compatible endpoint,
  and an API key; local SKU and zero-egress mode reject that configuration.
- `_model_router_from_settings` builds `RoutingPolicy(remote_allowed=settings.allow_remote_egress and settings.remote_model_url is not None, zero_egress_mode=settings.zero_egress_mode)`.
- `ModelRouter.decide` routes to `EndpointKind.LOCAL` when `zero_egress_mode` is true.
- `AnswerService.complete_model_request` calls `SolomonBoundary.sanitize_context` before `ModelRouter.complete`.
- `AuditJournal` records only metadata: endpoint, boundary crossing, prompt hash, prompt chars, and boundary mapping counts.

## Sent Vs Withheld

Local model path:

- sent: sanitized prompt generated by `build_answer_prompt` after recall and boundary sanitization;
- withheld: raw client identity when `SolomonBoundary.sanitize_context` maps it to placeholders such as `[CLIENT_1]`;
- recorded: model endpoint metadata and prompt hash, not the prompt text.

Remote ZDR path:

- available only when `allow_remote_egress=true`, `zero_egress_mode=false`, and `remote_model_url` is configured;
- sent: the same sanitized prompt;
- withheld: original privileged identifiers replaced by boundary placeholders;
- recorded: `crossed_boundary=true`, endpoint kind, reason, prompt hash, prompt chars, and cost if supplied.

## Boundary Round Trip

1. `AnswerService.answer` recalls live context and builds the answer prompt.
2. `AnswerService.complete_model_request` sanitizes the prompt.
3. `ModelRouter.complete` sends the sanitized prompt to the selected endpoint.
4. `SolomonBoundary.reidentify_response` demasks placeholders in model output, then flushes the mapping.

The opt-in live test `tests/test_model_live_integration.py` captures the model-visible local prompt and asserts raw `Client A` is absent while `[CLIENT_1]` is present.

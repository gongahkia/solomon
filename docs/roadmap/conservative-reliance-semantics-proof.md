# Conservative Reliance Semantics Proof

## Decision contract

This milestone permits **one architecture hypothesis**: a reversible normalized analysis view and one bounded,
declarative reliance grammar. The hypothesis is limited to recognizing a candidate `source -> registered authority`
reliance relationship more consistently when casing, harmless whitespace, quotation glyphs, or line wrapping vary.
It is not a claim of legal correctness, authority validity, or a basis to create, confirm, propagate, or rank an edge.

The immutable starting result is the two-hypothesis adversarial proof at `a21263c`; its final locked-holdout
suggestion precision is 1.000, recall 0.800, abstention 1.000, hard-negative false-positive rate 0.000, and false
positives per 100 items 0. The pre-change defects are recorded in
[the residual report](../evaluations/conservative-reliance-semantics-residuals.md). Nothing in this milestone may
weaken those exact existing-84 safety outcomes.

The protocol and the independent corpus are locked before extraction changes. Development fixtures may guide one
implementation; both the new 40-fixture holdout and the existing 84-fixture locked holdout are evaluated only after
the production implementation is frozen. Neither locked set may be edited, reclassified, or used for tuning.

## Representation contract

There is one canonical `NormalizedAnalysis` representation for a raw document fragment. It contains a normalized
display string and a per-analysis-character, monotone mapping to the original raw character interval. Case folding is
a matcher projection of that one representation, not a second source string or a rewritten evidence record.

Permitted transformations are deliberately small:

- Unicode NFKC expansion where it maps deterministically to its originating raw character;
- typographic single and double quotation marks to their ASCII counterparts;
- `§` to the matching token `section`; and
- a contiguous horizontal or wrapped whitespace run to one analysis space.

The normalizer must not reorder text, delete a token, merge sentences, discard punctuation that establishes a
boundary, rewrite authority names, manufacture an authority, cross a raw sentence boundary without a declared
two-sentence pattern, or normalize away negation or attribution words. A collapsed whitespace analysis character maps
to the entire original whitespace interval. A multi-character expansion maps each emitted analysis character to the
same raw interval. The raw evidence span returned to a reviewer is the minimal enclosing raw interval for the matched
analysis window, so slicing the original text reconstructs the evidence without using normalized text as evidence.

The authority fingerprint is computed only from the raw authority span: trim surrounding whitespace; apply NFKC;
replace `§` with `section`; case-fold; tokenize letters/digits; join tokens with `-`. It does not use a global alias,
an inferred title, an external authority database, or a value generated by a model. A candidate is allowed only when
that fingerprint exactly matches an authority registered for the source’s scope.

## Grammar contract

The grammar has bounded declarative patterns, each with an explicit actor, reliance predicate, local authority
association, raw evidence window, and all guards. A bare cue word (`under`, `follows`, `uses`, `relies`, `depends`,
`required`, `adopt`, `grounded`, `subject`, `derive`, or `having regard`) is never sufficient alone.

An affirmative match must have all of the following:

1. An in-scope registered authority in the same normalized sentence as the predicate, or in the immediately adjacent
   sentence in one explicitly declared adoption/anaphora pattern. The maximum evidence window is two adjacent
   sentences and 480 normalized characters. The authority-predicate distance in a single sentence is at most 240
   normalized characters.
2. A direct or adoption predicate that binds the document’s own voice to that authority: `relies on`, `depends on`,
   `required by`, `pursuant to`, `under … we/our conclusion`, `follows … for`, `uses … as`, `adopts … approach`,
   `grounded in`, `derives from`, `subject to`, `having regard to … conclude`, bounded replacement wording, or a
   declared cross-sentence adoption anchor.
3. A local actor that is the document author (`we`, `our`, `the firm`, `this advice`, `this assessment`, or a named
   source artifact) or an unambiguous imperative/operative construction. A third-party statement never transfers
   reliance to the document.
4. No negative guard in the same sentence or declared two-sentence window: quotation/reporting voice; client,
   counterparty, court, regulator, witness, opponent, training/extract attribution; `not`, `without`, `rather than`,
   `does not`, `did not`, `never`, `reject`, `decline`, `cannot`, or `no longer` when locally associated with the
   reliance predicate; historical/superseded/replaced-only context; hypothetical/conditional/example language;
   background/table/list/reference-only language; an explicitly independent conclusion; an unresolved choice among
   authorities; missing registry/scope; or more than one plausible authority association.
5. Exact raw evidence, source identifier, scope, and target fingerprint that can be reconstructed independently from
   the stored candidate explanation.

The grammar explicitly distinguishes these outcomes:

| Construction | Candidate result |
| --- | --- |
| Direct document reliance, local authority | candidate if all guards pass |
| Explicit cross-sentence adoption followed by an anchored proposition | candidate only within the one previous/current sentence window |
| Adoption predicate in one sentence | candidate if it binds the source’s actor and the authority locally |
| Attribution, quotation, client/counterparty/court/regulator/witness/opponent/training voice | abstain |
| Historical, superseded, replacement-only, hypothetical, conditional, rejected, negated, or independent conclusion | abstain |
| Background, table, bare citation, reference list, heading, or authority-not-registered | abstain |
| Multiple authorities without a unique bounded association, malformed/truncated citation, or raw-map failure | abstain |

Every accepted candidate explanation must report the declarative pattern ID, actor cue, predicate cue, authority
fingerprint, normalized-window offsets, raw evidence offsets, raw authority offsets, and every evaluated guard. An
unknown guard result or a non-reversible map is fail-closed abstention.

## Corpus and gate contract

The new corpus has at least 64 independently authored, fictional raw fixtures: at least 24 affirmative reliance
fixtures, 24 hard negatives, and 16 ambiguous fixtures. It is split before implementation into 24 development and 40
locked holdout fixtures. Each fixture provides its raw text, source/register authorities, scope, raw reference spans,
raw evidence span where affirmative, expected target or abstention, semantic category, rationale, and exact expected
suggestion count. The corpus is hash-verified and committed in a dedicated lock commit containing only the protocol,
corpus, annotations, loader, and verifier; it contains no production parser change.

The target gates for the new locked holdout are: suggestion precision at least 0.95; suggestion recall at least 0.80;
exact raw evidence-span accuracy at least 0.80; overlap accuracy at least 0.90; abstention accuracy at least 0.95;
hard-negative false-positive rate at most 0.05; no duplicate suggestions; and deterministic repeat output. These gates
are intentionally conservative: a fixture with no expected candidate is an abstention case, including every hard
negative and ambiguous fixture.

The frozen implementation is retained only if it also preserves the existing 84-fixture locked-holdout conditions:
suggestion precision exactly 1.000, recall at least 0.800, abstention exactly 1.000, hard-negative false positives
exactly zero, false positives per 100 fixtures exactly zero, no duplicate suggestions, exact evidence-span accuracy at
least 0.800, and fixed mutation stability at least 0.833. The existing 23-fixture control corpus must remain exact.

## Evaluation order and stop condition

The only permitted order is: existing controls; new development split; existing adversarial development split; fixed
mutations; normalization and raw-mapping property tests; freeze the production implementation; new locked holdout;
and existing locked 84-fixture holdout. Scenario and service lifecycle tests follow the frozen extraction evaluation.
No parser change is permitted after either locked evaluation. Evaluation records must preserve each raw error and each
raw evidence slice.

If any required safety condition fails, production source changes from this experiment are reverted while the locked
corpus, annotations, baseline, reports, and failed measurements remain committed. The conclusion is then limited
evidence against this grammar, not a reason to expand it again. The recommended next milestone would be a bounded
human-authored reliance form or review workflow that records a selected authority and rationale, rather than another
parser expansion.
